# Демо Quiz U по регламенту

1. Прочитай [регламент демо](../../../docs/DEMO_GUIDE.md). Для полного демо пройди всю матрицу из раздела 2 и применимые проверки из разделов 3–7. Для целевого прогона возьми запрошенные строки и связанные с ними проверки. Используй условия приёмки из раздела 8.
2. Зафиксируй коммит и существенные локальные правки, имя, ID и SHA-256 пака, фактический состав раундов, вопросов и медиа, настройки, браузеры, устройства и сеть. Для двух полных LAN-партий используй одну редакцию пака и одинаковые настройки. Проверь выдачу JSON и медиа. Возьми пак №895 для полного прогона, если пользователь не выбрал другой. Недостающие ветки покрой короткими партиями.
3. Запусти локальный режим на статическом HTTP-сервере, LAN — на игровом сервере по [инструкции запуска](../../../docs/README.md). Первый запуск делай в чистом профиле, для восстановления используй действующую сессию. В LAN выдели отдельный профиль каждому участнику. В каждой полной LAN-партии подключи пять игроков. Для ведущего на телефоне открой отдельный пульт в дополнение к общему экрану.
4. Управляй партией через обычный интерфейс. Для автоматизации используй действия браузера, чтение DOM и наблюдение за WebSocket. В полном прогоне не подменяй часы, таймеры, счёт или фазу. В полной партии пройди каждую ячейку с возвратом к табло, штатные переходы раундов и финал при его наличии в паке. Сверь финальное состояние, очки на клиентах и статистику, проверь отсутствие необработанных ошибок.
5. В LAN сверяй с сервером сроки чтения, обсуждения, личного ответа, общего аукциона и финала. Записывай момент открытия, остаток, паузу, истечение и отказ просроченного ввода. При реконнекте проверяй роль, доступные действия, очки и остаток таймера. Для экранов без числового таймера проверяй фазу и доступность действий.
6. Дополнительно выполни `npm test` в корне и в `server/`, а при запущенном игровом сервере — [штатное WS-демо](../../../tools/lan_demo.js) через `npm run demo:lan`. В PowerShell используй `npm.cmd`. Запиши результаты этих проверок отдельно от браузерных сценариев.
7. По каждой строке выбранной матрицы запиши «прошло», «дефект», «не проверено» или «не применимо» с причиной. Для дефектов сохрани роли, настройки, экран или ячейку, шаги, ожидаемое и фактическое поведение. Укажи, какие устройства и сети проверены физически, где была браузерная эмуляция и какие проверки остались. Удали токены и скрытые ответы из материалов для отчёта. Итог с датой, покрытием и ограничениями внеси в [TASKS.md](../../../docs/TASKS.md). После прогона останови запущенные для него серверы.
